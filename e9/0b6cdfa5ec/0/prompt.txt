we have a requirement to be able to pause execution based on an IO or BusIO or profinet signal.
That means in a production cell with many motion groups running on many controllers the user/person responsible for the cell wants to set a signal and then all the robots (and other cell machinery we are not concerned about atm) should pause motion and operation in a way so that it can be resumed again.
When it comes to robot motion in the SDK there seem to be two obvious mechanism to achieve this:
1. the pause_on_io parameter to motiongroup.execute and the like, which would pause robot motion on the RAE/WBR side; But the might be a gap in the Trajectory cursrors execution model and more specifically in the execution state handling (state machine) which seems to not interact well when such a pause happens.
2. the pause feature of the TrajectoryCursor; But this seems to have the issue of causing the motion to not ramp down and ramp up speed as nicely as with pause_on_io. The pause feature uses what is available via the execution websocket. 
Both claims need to be verified but maybe you can see other options too.

- `TrajectoryCursor._motion_group_state_monitor:1379-1381` — `is_ended` + `detach_on_standstill` → `break` → cursor detaches → `_request_loop` stops → `cntrl` generator ends → the `executeTrajectory` websocket is closed. - The `forward()` future resolves with a successful `OperationResult` (no `error`), with `final_location` at the pause point.

# 5. Cell-wide / controller-wide pause, hold, safety

**There is no cell-wide or controller-wide "pause all" / "hold" endpoint.** Pause is strictly per-motion-group over an execution websocket. What exists:

- `RobotControllerState` (`v2/models/robot_controller_state.py`) — from `ControllerApi.get_current_robot_controller_state` (GET `/cells/{cell}/controllers/{controller}/state`, L1368) and `stream_robot_controller_state` (websocket `/cells/{cell}/controllers/{controller}/state-stream`, L2896). - `SafetyStateType` (`v2/models/safety_state_type.py`) — 16 values incl. `SAFETY_STATE_PROTECTIVE_STOP`, `SAFETY_STATE_STOP_0/1/2`, `SAFETY_STATE_DEVICE_EMERGENCY_STOP`, `SAFETY_STATE_ROBOT_EMERGENCY_STOP`, `SAFETY_STATE_VIOLATION`, `SAFETY_STATE_NORMAL`, `SAFETY_STATE_REDUCED`. Read-only — no setter anywhere.
- `OperationMode` (`v2/models/operation_mode.py`) — `OPERATION_MODE_AUTO`, `_MANUAL`, `_MANUAL_T1/T2`, `_RECOVERY`, `_DISCONNECTED`, … Read-only.
- `RobotSystemMode` — `MODE_MONITOR`, `MODE_CONTROL`, `MODE_FREE_DRIVE`, `MODE_INITIALIZING`, `MODE_CONTROLLER_NOT_CONFIGURED`. Settable via `ControllerApi.set_default_mode(cell, controller, mode: SettableRobotSystemMode)` — PUT `/cells/{cell}/controllers/{controller}/mode` (L2560). This is the closest thing to a controller-wide gate: dropping to `MODE_MONITOR` rejects move requests. Not a pause.
- `CellApi` (`v2/api/cell_api.py`): `get_cell_status` GET `/cells/{cell}/status` (L1011), `set_cell_status` PUT `/cells/{cell}/status` (L1422), plus deploy/update/delete. Cell *status* is lifecycle, not motion hold.
- `SystemApi`: `get_system_status` `/system/status`, network/config/backup — nothing motion-related.
- Safety geometry models (`safety_zone.py`, `safety_zones.py`, `safety_geometry*.py`) are configuration shapes for zones, not runtime state.
- No `Hold`, `SafetyStop`, `pause_all`, or `estop` symbol exists in the client.
