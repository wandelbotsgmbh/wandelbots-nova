Key facts:
- pint is the de-facto standard (100× the downloads of anything else), but the **newest line dropped Python 3.11** — a hard dep would force `pint&lt;0.26` while we support 3.11. Its `Quantity` typing does *not* distinguish length from time statically; `after_start(50 * ureg.s)` type-checks fine and only fails at runtime (`DimensionalityError: Cannot convert from 'millimeter' ([length]) to 'second' ([time])`). Conversion is `q.m_as("mm")` / `q.to("mm").magnitude`.
- No mainstream library gives static dimension checking; the one that does (TypedUnits) is 0.0.x, Cython + protobuf.

## Design evaluation

**(a) keywords only** — zero deps, unit visible at call site, `TimeTrigger | DistanceTrigger` return is trivially typed. Type checker cannot stop `after_start(seconds=50, millimeters=3)`; needs a one-line runtime "exactly one" check.

**(b) pint hard dep** — +4 packages, ~300 ms import on every `import nova`, `pint&lt;0.26` pin for 3.11, no static gain over (a), and `50 * ureg.mm` needs a registry object the user must obtain from us (registries don't mix: quantities from a user's own `UnitRegistry` raise on conversion against ours). Rejected.

**(c) duck-typed quantity, pint optional** — `hasattr(x, "m_as")` → `x.m_as("mm")`; `timedelta` → `.total_seconds()`. No dep, works with any user-supplied pint registry (we never construct quantities, only convert theirs), also with astropy via `to_value`. Cost: signature becomes `seconds: float | timedelta | SupportsMAs | None`, which is honest but wordier; users who don't use pint see nothing.

**(d) own NewType** — `Millimeters = NewType("Millimeters", float)` gives static dimension safety with zero deps, but `after_start(Millimeters(50))` is noisier than `after_start(millimeters=50)` and says the same thing.

## Recommendation

Ship **(a)** now, with **(c) for `timedelta` only**:

```python
def after_start(*, seconds: float | timedelta | None = None,
                   millimeters: float | None = None) -&gt; TimeTrigger | DistanceTrigger
def before_target(*, seconds: float | timedelta | None = None,
                     millimeters: float | None = None) -&gt; TimeTrigger | DistanceTrigger
```

`timedelta` is stdlib, pydantic-native, and the only unit type users already have in hand. Accepting pint duck-typed (`m_as`) is a 4-line, dependency-free follow-up if a customer asks; it should not gate today's merge, and a pint hard dependency is not justified (3.11 pin, import cost, no static safety). The keyword names already carry the unit at the call site, which is the actual readability win over the current `after_time(0.3)`.
